# 视觉与设计决策

## 视觉系统

- 浅色：暖纸色 `#F6F1E8`，卡片 `#FDFAF5`，墨色文字 `#1F1D1A`，强调色灰绿 `#5C6B58`。
- 深色：深墨 `#141619`，表面层级 `#181B1E / #1D2125 / #23282D`，强调色降饱和为 `#A8BBA3`；靠亮度差与柔和阴影表达层级，不做简单反色。
- 正/负 delta 使用两个低饱和功能色（`#4F7456` / `#A5623F`，深色下 `#8FB894` / `#D09A7C`），只出现在事件列表与净增量热力图。
- 字体：系统衬线（`FontFamily.Serif`）用于计数器名称与当前值；数字启用 `tnum` 等宽数字特性，避免变化时抖动；标签/辅助信息使用小号无衬线。
- 动效：只保留一处签名动效——数值变化时 190ms 的轻微上移 + 淡入，配短触觉反馈；热力图格子错峰淡入；尊重系统动画缩放为 0 的「减少动态效果」。
- 无 emoji；图标全部来自 Material Icons（矢量）；无默认紫色、无描边卡片墙、无渐变堆叠。
- 主要点击区域 ≥ 48dp；提供内容描述；支持 RTL 基础布局。

## 交互原则

- 长按卡片 = 打开卡片菜单；长按右侧拖拽手柄 = 排序。两个手势分开，避免互相抢占。
- 危险操作（删除、替换导入、重置、范围撤销）都需要二次确认。
- 数值变化后提供一次只针对当前操作的 Snackbar 撤销，不提供无限撤销栈。
- 设置类偏好只影响展示，不改变历史数据；数据类操作都走同一 Repository 校验。
- 空状态给出一个明确动作，不堆叠多个 CTA。

## 歧义与决策记录

1. **长按卡片 vs 长按拖拽**：两个需求都要求长按。实现为「长按卡片 = 菜单」「长按右侧拖动手柄 = 拖拽排序」，并在普通区显示手柄与提示文案。这样两种交互都可用且不会互相抢占手势。
2. **事件时间相同**：排序使用 `(timestamp, id)` 全序，保证撤销范围与列表顺序确定。
3. **导入的负值允许策略**：不采用「保持 allowNegative=false 但允许负值」的破例状态，而是把受影响计数器改为允许负值，从而全局维持不变量；文档与冲突对话框都明确说明。
4. **热力图的「年视图」**：采用 GitHub 风格的滚动 52 周，而不是 1 月 1 日–12 月 31 日，避免年初出现大片空白。
5. **自动备份**：`android:allowBackup="false"`。数据只留本机，卸载即删除；迁移依赖 JSON 导出/导入。这样隐私声明与 Manifest 一致。
6. **数字类型**：对外模型按需求使用 `Int`（initialValue/delta），内部聚合使用 `Long`，并对单值设上限，避免 `SUM` 溢出。
7. **替换导入的清空范围**：替换会删除计数器、事件、标签与关联；之后只写入文件内容，因此「导入到空数据库完全一致」成立。
8. **合并时已有计数器元数据**：按需求只取事件并集；不覆盖名称、初始值、步长、置顶与排序。新计数器保留文件中的置顶/步长/初始值，但排序追加到普通区末尾。
9. **步长是会话属性**：主页与快速计数页的临时步长放在 ViewModel/Compose 状态中，旋转后保留（ViewModel），进程重启后回到默认步长。
10. **标签筛选时禁止拖拽排序**：重排只对全部普通计数器生效；筛选状态下若只对可见子集重新编号，会与隐藏计数器的 `sortOrder` 冲突，因此筛选时隐藏拖拽手柄和提示。
11. **重置/撤销的负值限制**：重置或撤销若会让 `allowNegative=false` 的值小于 0，会被拒绝并提示；正常历史状态下撤销总是回到曾经合法的旧状态，因此不会误伤。
12. **删除计数器**：直接删除计数器并级联删除事件；未被引用的标签会清理。历史事件本身仍不可变（随计数器一并删除）。
13. **大数字自适应字号**：数字文本按可用宽度自动缩小字号（下限 24sp），九位/十位数值不会撑破卡片、详情标题或全屏计数页；`Resize` 只在数字位数变化时发生，不改变对齐基线。
14. **日视图默认滚到最近**：52 周日热力图横向可滚动，进入时自动定位到最右侧的最近几周；月份刻度在滚动区域内绘制，向左滑可查看更早日期。
15. **主题/字体不重建 Activity，旋转/折叠交给系统重建**：`MainActivity` 只处理 `uiMode|fontScale|density`。系统深色模式与字体大小变化时保留导航栈和滚动位置，由 Compose 直接响应新的 `Configuration`；横竖屏与折叠屏切换仍走正常的 Activity 重建，因为部分厂商 ROM 在传感器旋转时自行处理 `orientation|screenSize` 会留下空返回栈。`NavHost` 另加兜底：在配置变化后与每次 `RESUMED` 时检查返回栈，若没有任何 Compose 目的地就自动回主页，避免只显示窗口背景的黑屏。
16. **标签删除的级联范围**：删除标签只删除 `tags` 行，`counter_tags` 通过外键级联清理；计数器和事件完全不动。若被删除标签正在作为主页筛选，`HomeViewModel` 检测到标签已不存在后自动回退到「全部」。
17. **标签数量不设上限**：`counter_tags` 只保证同一标签不重复关联；编辑器、导入、备份解析都不再截断标签。卡片与详情标签改为 `FlowRow` 自动换行，主页筛选行仍横向滚动，因此标签再多也不会撑破布局。
18. **卡片大小是纯展示偏好**：只改变主页卡片的留白、当前值字号和加减按钮尺寸，不进入 Room、不进入 JSON 备份，也不改变事件历史。紧凑档把数值与加减按钮并排，并把数值降到 `headlineLarge`、标题降到 `titleMedium`，因此比标准档明显更矮；紧凑档仍保持 48dp 触控目标，宽松档为 56dp。动画、标签换行与拖拽排序在三个档位下共用同一套逻辑。
19. **分/时是滚动窗口，默认仍是日**：分/时回答「最近一小时/一天发生了什么」，因此锚定当前时刻向前滚动，而不是自然日或自然小时；日/周/月继续按日历分桶，避免把「今天」拆成不完整的 24 个格子。热力图 key 统一为 `LocalDateTime`，日历粒度固定落在 00:00，分/时保留到分钟/整点。粒度选择是详情页的临时状态，不持久化，重新进入默认「日」。
